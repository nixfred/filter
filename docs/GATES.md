# GATES

Gate matrix for The Great Filter (filter.nixfred.com). This is the enforcement heart of the project (BUILD.md section 8). Every ACTIVE requirement in docs/PRD.md has exactly one canonical row here. A gate row states the exact observable pass condition, the mechanism that proves it, the evidence artifact it produces, its class, the earliest gate it must pass, whether it stands after launch, its owning discipline, and its status.

Authority: this document sits below docs/DECISIONS.md and docs/PRD.md and above docs/EXECUTION_PLAN.md (BUILD.md section 1). Gate classes, first phases, and requirement IDs are copied verbatim from docs/PRD.md and are never weakened here. Mechanism names use only the canonical CI job names, npm scripts, script filenames, and test file paths fixed in docs/CHARTER_COMMON.md, docs/CI_CD.md, and docs/TEST_PLAN.md, or the named manual protocols in docs/ACCESSIBILITY.md and docs/OPERATIONS.md.

Canonical counts: 97 ACTIVE requirement rows (94 BLOCK, 2 WARN which are OPS007 and OPS008, 1 MANUAL which is REL006) and 4 DEFERRED requirements (FR015, FR034, FR035, FR036) that are not gated in v1.

## Conventions

Class values are copied from docs/PRD.md: BLOCK a failure stops the gate, WARN a failure is recorded but does not stop the gate, MANUAL a human decision is required using a written protocol. Where a BLOCK row is proven by a written manual protocol (NFR001, ACC002, ACC004, ACC006, FR029, OPS004, REL002), the class stays BLOCK and the protocol is named in the Mechanism column; the class is never reclassified to reflect the mechanism.

First gate is the earliest phase at which the requirement must first pass, copied from docs/PRD.md, from the set G0, G1, G2, G3, G4, G5, G6, G7, G-LAUNCH.

Standing is YES when the check continues to run after launch (a continuous CI check, a per-deploy verification, a maintenance cadence, or standing branch protection) and NO when it is a point-in-time provisioning step or a one-time gate review.

Evidence for an automated row is the named CI job run tied to the gated commit, plus any named artifact that job uploads (a coverage report, Playwright traces, the built dist, a Lighthouse report). Evidence for a manual row is a file under docs/evidence/ named docs/evidence/<gate>_<checkID>_<shortcommit>.<ext> per BUILD.md section 15. The docs/evidence/ directory is created at G0 and retained in the repository.

Status is PLANNED for every row. It advances to VERIFIED only when the mechanism has passed against a real commit with retained evidence, never before (BUILD.md section 15, no fabrication).

Owner is the responsible discipline: Product, Engineering, Design, Performance, Quality, Accessibility, Security, DevOps, or Release.
